# Geo Go Go

An interactive world-map game for exploring countries and testing your geography knowledge.

[**Play Geo Go Go →**](https://kjeksfjes.github.io/geo-go-go/)

[![Latest release](https://img.shields.io/github/v/tag/kjeksfjes/geo-go-go?sort=semver&label=latest%20release)](https://github.com/kjeksfjes/geo-go-go/tags) [![Changelog](https://img.shields.io/badge/changelog-view-59636e)](CHANGELOG.md)

Built with Vue 3, TypeScript, Vite, Natural Earth Admin-0 Map Units, `d3-geo`, and `flag-icons`.

The map starts with Natural Earth's 1:50m Admin-0 Map Units. A **High detail** toggle lazily loads the corresponding 1:10m units when requested. This keeps the initial download and render light, avoids changing geometry in the middle of a gesture, and makes coastlines and small countries clearer at close range when desired. After each resolution has rendered once, its projected SVG paths are cached so later switches are immediate at the current map size and projection. The **Bathymetry** toggle adds seven noninteractive ocean-depth bands (200m, 2,000m, 3,000m, 4,000m, 5,000m, 6,000m, and a darkest 7,000–10,000m trench band) behind the country layer for relief-style experiments. The adjacent **Relief** toggle adds six similarly simplified elevation bands (500m, 1,000m, 1,500m, 2,250m, 3,000m, and 4,000m) without changing map interaction. The map also shows major ocean names at world scale and introduces names of seas, gulfs, bays, and other smaller waters as you zoom. These labels are noninteractive and follow the active projection and map movement. The **Water names** toggle can hide them; labels also disappear temporarily during map dragging and zooming so they do not distract from motion.

On touch-first devices, rapid two-finger zooms, one-finger pans, and animated zooms such as Reset view can temporarily use a lower-density canvas preview. Invisible country hit paths pause during the preview; answer highlights and neutral land remain visible. Normal hit targets return after movement. Coverage-valid cached rasters bridge the wait for full-density detail, with a magnification guard on the world overview and wider detail crops for touch pans and mobile animations. Slow pinches and other desktop browsers retain their existing rendering policies. The user has accepted high-detail zoom and pan responsiveness on their iPhone, including bathymetry.

Desktop Firefox uses a lower-density, wider cached preview during panning, wheel zooming, and automatic camera animations. Country borders, selected-country and quiz highlights, tiny-country location rings, and keyboard focus remain visible during movement. The preview may be softer; full-density detail returns at rest. Earlier refresh requests and brief cached-detail reuse help bridge worker latency without showing uncovered bitmap edges; the world overview retains its magnification guard. This policy is automatic on Firefox with a fine pointer and hover support, independent of diagnostic flags, and applies to both map detail levels. Chrome and touch-first devices keep their existing rendering policies. The user accepts the final desktop Firefox movement quality and responsiveness with visible borders. Chrome and mobile rendering policies were verified in source; no new agent browser testing was performed.

For desktop or mobile movement troubleshooting, append `?gesture-debug` to the URL (or `&gesture-debug` if it already has query parameters). This enables a rendering-status button and recording of the last completed mouse/touch pan, pinch, wheel-zoom burst, or automatic camera animation with its short settling window; click the button to copy the report. Reports include the active rendering policy, map settings, browser/viewport information, relative pan displacement, RAF gaps, preview/renderer/buffer transitions, fallback reasons, and worker drawing and bitmap handoff timings. Schema `geo-go-go.last-gesture.v4` identifies the movement and input source. Wheel reports include the existing 140 ms wheel-end delay; reduced-motion jumps are not animations and do not create an animation report. Only the latest report is kept in memory; nothing is sent automatically. Recording and the button are disabled without the URL flag. This is separate from the existing `?debug` map panel. The former `early-pan-refresh`, `desktop-preview`, and `no-preview-borders` experiment flags have been removed and have no effect.

Mouse-pan reports also include `panStartup` timings from pointer-down to first move, drag activation, first camera change, and first RAF callback. Handler durations and event timestamp ages help distinguish application startup work from late event delivery. These timings include any intentional hold before moving; event ages are browser timestamp measurements, and neither camera updates nor RAF callbacks prove when pixels reached the display.

The scale bar shows an approximate distance near the center of the current map view. It is visible by default, can be hidden in map settings, and supports metric, imperial, and nautical units. Metric is the default; both visibility and units are remembered between visits.

Settings are grouped into **Map appearance** (High detail first, followed by Bathymetry, Relief, Water names and Projection), **Quiz**, and **Navigation & scale**. Quiz preferences stay available in every mode and identify which quiz they affect. **Reveal clicked country names** shares the Find the country quiz’s existing **Always show** preference. In its answer card, **What did I click** reveals the clicked country and **Always show** control; enabling that control checks it and saves the preference, while disabling it hides the clicked country again. Desktop settings use two columns, with Map appearance on the left and Quiz above Navigation & scale on the right. Language stays visible in the header on desktop and mobile, is offered as English/Norsk in the introductory help invitation, and also appears at the top of mobile settings. Help stays inside each setting’s card, with mode labels for quiz preferences. **Limit country zoom** affects automatic country framing; manual zoom remains unrestricted by that preference. The single-column mobile panel, and shorter desktop windows, scroll only when needed to fit the available screen height.

It defaults to a conventional Mercator projection. Mercator preserves local shapes and angles well, while enlarging areas toward the poles in the familiar way. The World view wraps horizontally at every zoom level when panning across the map edge.

## Run locally

All country display names are supplied by the app in `src/data/country-names.json`, keyed by canonical country identity with explicit `en` and `nb` strings. Country cards, quiz questions, feedback, hover labels, and accessibility labels share this catalog; browser/OS language databases and flag codes do not supply names. Norwegian state names follow the Bokmål forms in [Språkrådet's state-name list](https://sprakradet.no/stedsnavn-og-navn-pa-statsorgan/navnelister-norsk-skrivemate/utanlandske-stadnamn-navn-pa-stater-og-sprak-transkripsjon/navn-pa-stater/), with explicit app labels for territories and non-state identities. `npm run check:country-names` verifies exact identity coverage and nonempty translations in both languages, and runs as part of `npm run build`. New country identities must include both names; there is no source-name or browser-translation fallback for known countries.

```sh
npm install
npm run dev
```

Open the local URL printed by Vite, then hover, focus, or click a country. Use the EN/NO control to switch between English and Norwegian Bokmål. The app starts in the browser's language when supported and remembers a manual choice. Scroll over the map to zoom around the pointer; selecting a country smoothly zooms the map to its bounds. Drag a zoomed map to pan, or switch between Mercator, Winkel Tripel, Equal Earth, and Natural Earth projections with the map control. Regional Equal Area uses an azimuthal equal-area projection; Europe uses a 10°E, 52°N origin and fits the displayed European map units. Western Europe and Eastern Europe have explicit fit frames. The hierarchical region selector can isolate and focus a continent or a smaller subregion. Projected paths are reused when the projection and display geometry are unchanged; region-specific views may need new paths. The selector tree is navigation, not a source of geographic inheritance: Europe uses Natural Earth's UN-style region classification, whereas Western Europe is a separate playable grouping that retains Greenland. Its dropdown uses `@zanmato/vue3-treeselect` for tree navigation and single selection.

Regional views limit zoom-out and panning to the selected area with some surrounding space. Nearby land outside the region appears in a quieter color for orientation but remains non-interactive; only the selected region contributes quiz countries. The World view retains unrestricted global navigation.

The **Find the country** mode shows a flag and country name from the active region. Click its map location to answer. Each correct first attempt earns one point; after every answer, use **Next country** to continue. A round asks each eligible state once; changing regions inside a quiz starts a new round with confirmation once a question has been answered or skipped. A country's principal map unit must belong to the region for it to become a regional question; overseas units remain visible and interactive but do not make an otherwise out-of-region parent country a question. Explicit playable groupings keep their own membership rules. Territories remain visible on the map but are not used as quiz questions. After an answer, clicking the map or pressing Space also advances, so the player can continue without moving back to the button. With **Country markers** enabled in Quiz settings, tiny eligible countries get neutral screen-sized dots in regional or zoomed views while their real shapes are too small to use. A filled dot selects its country; overlapping dots combine into a numbered zoom group with a faint circle around the area it represents. Clicking a group distributes small dots toward its countries before zooming. Newly enlarged countries receive temporary dots that fade away. The dots never identify the current answer, and the underlying geography stays unchanged.

The **Name the country** mode frames and highlights a country from the same active-region quiz pool without displaying its name or flag. With Country markers enabled, hollow outlines help locate tiny islands; overlapping outlines merge to keep scattered island groups legible. Type in the country-answer field to filter the app's English or Norwegian names, then use arrow keys and Enter or tap a suggestion to submit. Matching ignores case and accents, with prefix matches first. Turkey is displayed in English and Tyrkia in Norwegian; Türkiye/Turkiye also finds that country. Clearing the field closes suggestions. **Skip** finishes the current question for zero points and shows a Skipped card before **Next country**; use **Cmd+Enter / Ctrl+Enter** from the answer field as a shortcut. Answers use canonical country identities, and all eligible regional names remain available throughout the round. In settings under **Quiz → Answer suggestions**, choose **Selected region** or **All countries**. All countries broadens the answer list to every quiz-eligible country while retaining regional questions; the preference is remembered and defaults to Selected region. Both quiz preferences are available in every mode, with notes identifying which quiz they affect. An outside-region **My guess** temporarily shows the country globally, and Next returns to the round’s selected region. After submission, the question heading stays in place and the chosen name remains in a read-only field. Correct answers receive green confirmation; wrong answers receive a red field border. The **Reveal answers automatically** quiz preference controls showing the correct name after wrong guesses and skips, is remembered separately from Find the country, and defaults off. **Show answer** reveals a hidden answer for the current question. **Always show** enables the shared saved preference and displays a check. Turning it off hides the current revealed answer and restores **Show answer**, matching Find the country’s clicked-answer controls. Hidden answers also stay unnamed in map tooltips and accessibility labels. Scoring, Next and replay follow the same quiz flow. After a wrong answer, **My guess** focuses the chosen country without changing the answer or score. The Reka UI combobox loads only when this mode is used; desktop users can answer continuously from the keyboard, while touch users open the software keyboard deliberately. A map tap also focuses the answer field while a Name the country question is awaiting a guess; panning and pinching do not focus it.

Natural Earth map units are rendering parts, not automatically separate quiz areas. By default, parts sharing one quiz identity are dissolved into one geographic interaction unit, removing internal administrative edges (as with Bosnia and Herzegovina, Serbia, and Belgium). The small opt-in list in `src/data/meaningful-map-units.json` keeps genuinely distinct components separate: mainland France and French Guiana, for example, remain separate geographic units tied to the same France answer. Hover and click target the complete geographic unit; in Explore, the clicked unit highlights strongly while other units of the same quiz identity highlight softly. Answer checking and the country card use the shared quiz identity. The country card can also show the selected component's own name and a smaller educational type label.

Entering either quiz starts a fresh round in the currently selected region. Leaving for Explore or switching quiz modes ends the round. Leaving, restarting, or changing region asks for confirmation once a question has been answered or skipped; an untouched first question can be abandoned immediately. Completed rounds remain on their results until replay or leaving the mode. Recovery after reloading or reopening the browser mid-quiz is deferred in TASK-008.

Explore-mode selection has a separate, small camera/selection policy in `src/data/selection-behavior.json`. Clicking a configured main country unit highlights all of that quiz identity's parts, while clicking a named component highlights that component strongly and its siblings softly. Nearby components can share a camera footprint (for example mainland Italy, Sicily, and Sardinia); distant components keep their own click-to-zoom focus. Hover is broader: every visible part sharing a quiz identity highlights together, even when its camera focus remains local. In quiz feedback, a country's parts highlight together by default, whether the answer is correct or wrong. The same config lists distant components that retain a secondary highlight when the main country is clicked, and become primary themselves when clicked. These visual groups do not change quiz identity or camera focus.

## Geographic data

Marine names and approximate label positions come from Natural Earth's [1:10m Geography Marine Polygons](https://www.naturalearthdata.com/downloads/10m-physical-vectors/10m-physical-labels/). `scripts/import-marine-labels.py` combines the source geometry with the reviewed English and Norwegian Bokmål names in `scripts/marine-label-names.json`, then generates `src/data/marine-labels.json`. Every label has an explicit value in both languages; established Norwegian exonyms are used where verified, while other labels intentionally retain the authoritative international or local name. The five ocean anchors are placed separately because the source divides oceans into multiple polygons and some span the map seam. The review decisions and sources are summarized in [`docs/marine-label-audit.md`](docs/marine-label-audit.md).

Maintained editor changes live in `src/data/marine-label-overrides.json`, separately from the generated source catalog and guides. The runtime applies complete placement snapshots, added names, removed source IDs, and language-specific text overrides after the generated data and older authored refinements. This preserves the edited geometry, explicit font sizes, letter spacing, and line breaks when source data is regenerated. The current overrides replace the combined Atlantic label with North/South Atlantic labels using stable IDs `ocean:atlantic:north` and `ocean:atlantic:south`; these use the matching source-piece highlights in the editor and do not create quiz identities. The build validates both the generated source data and the maintained overrides.

The bathymetry POC uses Natural Earth's nested 1:10m vector bathymetry bands. `scripts/import-bathymetry.py` merges and simplifies the selected 200m, 2,000m, 3,000m, 4,000m, 5,000m, 6,000m, and 7,000m source files into `src/data/bathymetry.json`; the deepest contour supplies one shared 7,000–10,000m trench treatment. The bands are projected by the same D3 projection and transformed by the same pan/zoom group as the country geometry; they do not participate in hit-testing or quiz behavior.

The land-relief POC derives six vector elevation bands from NOAA NCEI's ETOPO 2022 ice-surface model. `scripts/import-relief.py` uses interpolated contours from a sampled NetCDF grid, removes tiny fragments, and simplifies the result into smooth SVG-ready geometry in `src/data/relief.json`. At runtime, the projected bands are clipped to the currently visible geographic units, so regional filtering and regional display geometry remain authoritative. Country borders and translucent interaction states are rendered independently above the relief, preserving some elevation contrast during hover and quiz feedback.

The checked-in map assets come from Natural Earth 5.1.1 **Admin-0 Map Units** at [1:50m](https://www.naturalearthdata.com/downloads/50m-cultural-vectors/50m-admin-0-details/) and [1:10m](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-admin-0-details/). `scripts/import-natural-earth.py` converts their shapefiles to compact GeoJSON. The 50m table defines the unit IDs and metadata; the 10m file supplies geometry for the same units, keeping detail switches stable. `GU_A3` identifies a source map unit, `ADM0_A3` groups units into a country/quiz identity, and `SOV_A3` records the separate sovereign relationship. Dependency parent links are optional. Natural Earth's `REGION_UN` and `SUBREGION` fields provide the canonical, broadly UN M49-style geography. Custom game groupings (Western Europe, Eastern Europe, Balkans, the three Asia practice groups) are overlays, never inherited into a parent continent. Western Europe (24 quiz countries) and Eastern Europe (22) are mutually exclusive game groups. Eastern Europe uses the Norwegian Wikipedia article's [country table](https://no.wikipedia.org/w/index.php?title=Øst-Europa&oldid=25912362#Land), adapted to place Greece in Western Europe and retain Turkey in Eastern Europe. Western Europe contains the remaining canonical European country identities, including the Nordic states, Spain, Portugal, Italy, Greece, and the Mediterranean microstates; Greenland and the Faroes retain their Explore membership. Balkan remains a smaller practice group overlapping both broad groups, with Greece in its western overlap and Turkey in its eastern overlap. These are explicit game policies rather than strict UN subregions; every country eligible for the Europe quiz belongs to exactly one broad group. Turkey remains an additional Eastern Europe question without changing its canonical continent membership. Initial views focus on the practice area without splitting Russia or Turkey into new quiz identities. State eligibility is a separate game rule.

Asia's practice groups are **Middle East & Western Asia / Midtøsten og Vest-Asia** (20 quiz countries), **Central & South Asia / Sentral- og Sør-Asia** (13), and **East & Southeast Asia / Øst- og Sørøst-Asia** (17). They cover all 49 countries in the Asia quiz exactly once. The western group uses the source's Western Asia classification plus Iran and Egypt; the central/southern group combines Central and Southern Asia excluding Iran, and the eastern group combines Eastern and South-Eastern Asia. Egypt remains an extra practice-group member while its canonical continent stays Africa. Russia's principal unit remains European and is not added to the Asia quiz. Hong Kong, Macao, Siachen, and the Australian Indian Ocean Territories retain their existing Explore-only treatment. Each wider group has an explicit regional projection frame; country identities, state eligibility, and geometry are unchanged.

Natural Earth's "Geo unit" type does not say whether a split should be an independent game area: it marks Vojvodina and French Guiana alike. The explicit meaningful-unit list provides that semantic decision. The generated `combined-geographic-units-50m.json` and `combined-geographic-units-10m.json` contain dissolved geometry for unlisted multi-part identities; regenerate them with `scripts/build-geographic-units.py` after changing the map-unit list.

Extra 10m geographic units within an existing country (such as Brčko District and Iraqi Kurdistan) are retained in `ne-10m-canonical-fill-geometries.json` and dissolved into that country's detailed geometry, even when it has only one canonical 50m unit. They do not create extra quiz answers. `country-taxonomy.json` also records curated quiz identity overrides, so source regeneration preserves choices such as Åland belonging to Finland's quiz identity.

Other previously omitted 10m pieces are retained in generated `supplemental-land.json` as neutral visual land at both detail levels. They have no country/quiz identity or regional membership; their fill blocks clicks on underlying country geometry while affiliations are undecided. Both renderers share the same small SVG land pass.

`scripts/build-geographic-units.py` also generates `supplemental-country-geometries-50m.json` and `supplemental-country-geometries-10m.json`. These sparse overrides exclude supplemental land and replace adjoining coarse/detailed difference pieces through one shared repair footprint for neighboring countries. The footprint includes coastal endpoints and seaward edges, and follows natural geometry intersections rather than a rectangular crop, so both sides of national borders join the detailed supplemental outline together. The generator checks shared-edge coverage and coastal contacts, and rejects newly overlapping country shapes. The overrides exclude supplemental land from country/component geometry wherever the source overlaps it, so low-detail fill, outlines, highlighting, hit-testing and focus use the same area separation as high detail. Supplemental boundaries retain their detailed source shape at both resolutions; no simplification may erase a small area. Quiz unions start from the corrected Explore geometry and then apply only the existing curated merge policies. Exact source defects are repaired through `scripts/map-geometry-corrections.json`, with assertions that stop regeneration if the expected source coordinates change. See [the boundary audit](docs/supplemental-boundary-audit.md) for provenance and verification.

Claim boundaries are separate noninteractive linework in `disputed-boundaries.json`. `scripts/import-disputed-boundaries.py` extracts the explicitly curated Hala’ib Sudanese claim line from Natural Earth’s 10m Admin-0 Boundary Lines – Disputed Areas source. A shared dashed SVG overlay sits above country fills and highlights in both rendering modes and detail levels, respects region visibility and horizontal map copies, and is hidden in quiz mode. It does not change land, country affiliations, hit targets or quiz answers.

Public Explore area labels are separately opted in through `supplemental-area-labels.json`. The two Korean DMZ source pieces form one dissolved hover, click, and keyboard-focus shape with a single area card; their shared dividing line is separate, noninteractive dashed linework. `scripts/build-geographic-units.py` generates these grouped Explore shapes and dividing lines in `supplemental-area-geometries.json`, preserving the individual source pieces for quiz policies. UNDOF, Akrotiri, Dhekelia and Bir Tawil have their own area cards without country selection. Bir Tawil’s card explains that neither Egypt nor Sudan claims it; it stays separate in Explore and merges into Sudan’s shape only for the quiz. Guantánamo's card identifies the US-administered leased area; its explicitly curated `quizEntityId` associates it with Cuba for Explore country highlighting, without asserting US sovereignty or introducing a new quiz answer. All named areas' dashed boundaries share Baikonur's internal-boundary color, width, and dash pattern in `mapPalette.ts`, with the same SVG pass above both renderers at both detail levels.

`quiz-map-merges.json` separately defines quiz-only simplifications: Akrotiri and Dhekelia merge into Cyprus, Guantánamo into Cuba, Baikonur into Kazakhstan, the restored UNDOF strip into Syria, and Bir Tawil into Sudan. Bir Tawil’s quiz-only merge keeps the country-selection border near the 22nd parallel; it is a game simplification, not an assertion that Sudan claims or administers the area. The UNDOF policy applies only to source piece `SYU`, not to the wider Golan boundary. The Korean DMZ's southern source half (`KNX`) merges into mainland South Korea, and its northern half (`KNZ`) into North Korea, retaining the dividing line while hiding the outer buffer boundaries. Each policy names its exact `geographicUnitId`; South Korea targets `subunit:KOR`, leaving Jeju and other components unchanged. Explicit `excludeSourceIds` remove coarse-boundary overlap with the opposite DMZ half in quiz mode only.

`scripts/build-geographic-units.py` also generates `quiz-merged-geometries-50m.json` and `quiz-merged-geometries-10m.json`, keyed by geographic unit ID, from country/component geometry and the curated supplemental/lease shapes. The quiz uses these dissolved geometries for country fill, outline, hit-testing, focus, and answer feedback, omitting the separate area overlays and internal boundaries. Explore source geometry, labels, and sovereignty metadata remain unchanged; other buffer zones and disputed areas are not automatically merged. Quiz projection variants reuse unchanged Explore paths and project only the merged units, keeping their fitting coordinate system stable. The canvas worker retains the current scene's parsed paths for reuse on updates; compatible projection/viewport updates keep a front frame visible until its replacement arrives.

Curated `leasedAreas` in `meaningful-map-units.json` retain leased land such as Baikonur as clickable components, with subtle internal boundaries rather than water-filled holes. They preserve their host country's quiz identity; the component label describes the lease operator separately. After importing new source geometry, run `node scripts/build-leased-areas.mjs` to regenerate `leased-area-geometries.json` from the matching 10m country holes. Both detail levels use the same small lease boundary so clicking and highlighting remain consistent.

Selected [Natural Earth Admin-0 Map Subunits](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-admin-0-details/) at 50m and 10m supply source geometries and names for places within a single map unit, including Alaska, Hawaii, Corsica, Tasmania, Jeju, Hainan, and Japan's main islands. `SU_A3` identifies the subunit, `GU_A3` links it to the parent map unit, and `ADM0_A3` links it to the country/quiz identity. Only the subunit IDs opted in by `meaningful-map-units.json` become named components. The importer `scripts/import-meaningful-subunits.py` dissolves all other subunits of each selected map unit into one unnamed interactive remainder, so source splits do not automatically become educational components. The same config holds a small set of optional English/Norwegian name and type overrides. Natural Earth's `TYPE` field is usually only "Geo unit" or "Geo subunit," not a useful educational label such as "State" or "Archipelago"; informative source types are used when available, and otherwise a curated type may be shown or omitted. The remainder of each selected map unit is retained as an interactive geographic unit, so no country geometry is discarded. Subunit selection never changes the country used for quiz answers.

Some named components are not separate Natural Earth Admin-0 subunits. Crete and the three Caribbean Netherlands islands use [Natural Earth 1:10m Admin-1 States and Provinces](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-admin-1-states-provinces/) names and boundaries. The importer uses those boundaries to identify complete Admin-0 coastline polygons at each map resolution, preserving the source country outline without a rough crop. `independentAdmin1RegionsByMapUnit` records these explicit semantic choices; `sourceSubunitIdsAt10m` reconciles source subunit IDs that split differently between 50m and 10m. Regeneration takes both Admin-0 subunit shapefiles and the 10m Admin-1 shapefile.

For a map unit with regional display geometry, the importer removes selected components from the regional remainder too. Kaliningrad is therefore separate from the rest of Russia without being drawn twice in the Europe view; the existing dashed Europe–Asia division remains on the Russian remainder.

`independentCoastlineComponents` explicitly names whole islands that are not separate source subunits. Seed points identify single polygons in the checked-in 10m map-unit atlas; the importer removes each polygon from its existing parent component and retains the same small shape at 50m when the coarse source omits it. Big and Little Diomede use this mechanism, with their Russia/USA identities and parent map-unit region membership preserved. Explore hover labels and the existing country card show component names; Little Diomede’s type text mentions the Diomede / Inalik community. Naming follows the [National Park Service](https://home.nps.gov/anch/learn/historyculture/how-close-is-alaska-to-russia.htm), [National Archives community guide](https://www.archives.gov/files/research/native-americans/communities/alaska-nativecommunities-guide.pdf), and [Store norske leksikon](https://snl.no/Diomedes%C3%B8yene). No permanent map labels or new quiz identities are added.

Natural Earth does not split Russia's European and Asian territory into map units. The Europe view therefore uses an optional **regional display geometry** for Russia at both resolutions. It is derived by intersecting the original Natural Earth Russia map unit with the European side of [Alexandr Trubetskoy's Europe–Asia boundary](https://sashamaps.net/resources/europe-asia-boundary/), following the Caucasus/Caspian, Ural River and Ural Mountains toward the Kara Sea. The source [GeoJSON boundary](https://github.com/sashatrubetskoy/asia_europe_border) is used with attribution. The artificial closing edges of the European-side polygon lie outside Russia; the cut through Russia follows the published geographic boundary, not a rectangular crop or SVG mask. The European Russia shape is filled separately from its outline: true Natural Earth edges retain the ordinary border style, while the cut through Russia is drawn as a subtle dashed geographic-division line.

`scripts/build-regional-display.py` generates the separate 50m/10m override assets from the boundary GeoJSON and the checked-in Natural Earth units. The base Natural Earth geometries are never modified. Region-specific geometry is used consistently for projection fitting, drawing, hit-testing and click-to-zoom; the map-unit ID and Russia quiz identity remain unchanged. Other transcontinental units such as Turkey and Kazakhstan have no override yet and may need their own geographic treatment later. To regenerate, install Shapely for the build script, download the boundary project's GeoJSON export, then pass its file path to `python scripts/build-regional-display.py`.

The detailed layer is matched back to 50m map-unit IDs, so switching resolution cannot change the selectable unit set. Detailed geometries pass a spherical-area sanity check; malformed features fall back to the safe 1:50m unit.

Antarctica is imported separately as non-interactive background land at both detail levels, outside the country and quiz datasets. `scripts/import-background-land.py` extracts its map unit from the [Natural Earth 5.1.1 GeoJSON sources](https://github.com/nvkelso/natural-earth-vector/tree/v5.1.1/geojson): pass `ne_50m_admin_0_map_units.geojson` and `ne_10m_admin_0_map_units.geojson` to regenerate `background-land-50m.json` and `background-land-10m.json`. High-detail background geometry loads with the existing detailed atlas. The current projection fitting and region camera policies remain based on selectable geography.

## Architecture at a glance

Water names draw in their own noninteractive SVG overlay. Mouse-down and map movement hide that overlay with opacity, keeping its text layout outside the interactive map's SVG. The overlay is removed when Water names is disabled or either quiz mode is active; Explore retains the saved preference.

Water labels use compact geographic guides and interior rectangles prepared from Natural Earth 5.1.1 marine polygons by `scripts/import-marine-label-paths.mjs`, with authored refinements in `src/data/marineLabelPaths.ts`. Pass the pinned `ne_10m_geography_marine_polys.geojson` to regenerate the placements. Broad waters prefer horizontal, balanced two-line names within sampled open-water rectangles; elongated waters follow their main direction and interior cross-sections, with curves where meaningful. Preparation checks water samples against land at both map detail levels and assigns typography tiers from spherical water area, avoiding polar size exaggeration. Every imported non-ocean water name must have a prepared placement; validation fails if one is missing. Narrow passages and winding fjords use authored corridors where automatic preparation cannot find a suitable guide. Their text uses the available path length, prioritizing readability over strict coastline clearance. Only compact placements ship to the browser, where text metrics are cached and layout runs after gestures settle. Font sizes are chosen in the unzoomed map and scale directly with map zoom; viewport checks determine visibility rather than shrinking text. Water names do not suppress one another when their label bounds overlap, including seas within larger oceans.

Data flows from geographic units and quiz identities through a D3 projection into a painted map and a separate interaction layer. The map reports clicks back to the app; the app owns selection and quiz state.

- **Data and rules:** `src/data/countries.ts` links Natural Earth map units, meaningful geographic components, and quiz identities. `src/data/regions.ts` defines geographic membership and playable groups; `src/data/quizCountries.ts` decides which identities can be questions. Curated exceptions live in the JSON configuration under `src/data/`.
- **App state:** `src/App.vue` owns mode, active region, detail level, and the selected identity/component. `src/composables/useCountryQuiz.ts` owns the question sequence, answers, and score. They pass state to the map and receive selection events from it.
- **Projection and interaction:** `src/components/WorldMap.vue` coordinates the map. `src/composables/useMapProjection.ts` generates and caches projected paths; `src/composables/useMapZoom.ts` manages the camera. The small policies in `src/logic/mapInteraction.ts` and `src/logic/mapFocus.ts` decide highlight, click, and focus behavior without drawing the map.
- **Drawing:** `src/components/CanvasMap.vue` and `src/workers/mapRaster.worker.ts` paint the default map off the main thread. SVG paths remain for hit-testing and crisp highlights, and can draw the full map as a fallback. `src/components/MarineLabels.vue` draws labels separately; `src/data/mapPalette.ts` keeps canvas and SVG geographic colors in sync.

## Norway counties

Choose **Norway counties / Norges fylker** in the header's Map selector. The map contains only the land of Norway's 15 counties, including coastal islands; foreign land, Svalbard, and Jan Mayen are absent. Use **Explore**, **Find the county**, or **Name the county**. Each quiz visits all 15 counties once in shuffled order, using the existing answer field, feedback, scoring, skips, reveal controls, and keyboard shortcuts. County names retain their official Norwegian spelling in both interface languages. County identities (`no:county:<official number>`) stay independent of country and geographic-component identities.

Pan, pinch, and wheel zoom use the existing navigation code. Small counties receive hollow location markers with larger tap targets. Both quiz modes omit hover tooltips and conceal county names in map accessibility labels; answer suggestions remain available. Reset view shows the whole county map. County and country maps use the same settings panel and remembered preferences, including detail, projection, terrain, water names, markers, scale, and quiz behavior. County answer suggestions always cover all 15 counties. County geometry loads only when this map is selected, and the finer geometry loads only when High detail is enabled. The existing Canvas renderer and SVG fallback use the same county paths; `?renderer=svg` selects the fallback for comparison. Help tour and view-link controls remain in the country map. Locally bundled county coats of arms appear in Explore cards, Find questions, answer suggestions, and revealed answers; Name questions conceal them until answered. Asset sources, checksums, and usage metadata are recorded in `src/assets/county-arms/sources.json`.

The checked-in polygons combine Kartverket's 2026 county boundaries with the existing Natural Earth 5.1.1 1:10m Norway land outline. This clips away offshore administrative areas; the resulting coastline is a generalized atlas coastline, not cadastral precision. The importer checks all 15 official county numbers/names, preserves shared borders while simplifying at 350 m (overview) and 80 m (high detail), and orients rings for D3. County boundaries are attributed to Kartverket under CC BY 4.0; Natural Earth's coastline is public domain. See [source provenance and checksum](docs/norway-counties-source.json).

To regenerate, download the archive recorded in the provenance file and run `python scripts/import-norway-counties.py <official GeoJSON zip>` with Shapely >= 2.1 and pyproj installed in a separate Python environment. These are import tools only; the app has no new runtime dependency or live geographic API. `npm run check:counties` validates coverage, names, coordinates, polygon rings/winding, geographic fixtures, and both detail levels, and runs as part of the build. Visual and device acceptance remain with the user.

## Start and stop the local server

From the project directory, run `npm start` to serve the app at `http://localhost:5173` and your computer's local network address, so other devices on the same network can open it too. Keep that terminal running; Ctrl+C stops the server normally.

If the original terminal is unavailable, open a new terminal in the project directory and run `npm stop`. This finds the project's Vite server on port 5173 and stops it, closing both localhost and local-network access. It refuses to stop an unrelated process using that port. Saved project files and browser drafts are unaffected. `npm run dev` remains available for localhost-only development. Both start commands require port 5173 to be free instead of silently choosing another port.

## Map view links and local view commands

In Explore mode, **Copy view link** copies a URL containing the geographic center, map zoom, region and projection. For example, `http://localhost:5173/#view=59.2,5.7,128&region=world&projection=mercator` opens a close view of southwest Norway. The same fragment works under the published site's base path. Latitude comes before longitude; zoom is the map's existing scale multiplier (1–16384). Normal region and projection navigation limits still apply. Different viewport shapes show different surrounding areas. Links open Explore mode and leave language, detail and visual layer preferences unchanged.

Opening a different view fragment in the same tab applies it without a reload; Back and Forward navigate between linked views. Copying a link does not continually rewrite the address while panning or add history entries. Invalid view fragments are ignored.

While `npm run dev` is running, move the most recently focused connected map tab with:

```sh
npm run show:view -- --lat 59.2 --lon 5.7 --zoom 128 --region world --projection mercator
```

Use `--url http://localhost:5174` if Vite is on another port. The command uses a local-only POST endpoint and Vite's existing WebSocket connection, without browser automation or polling. It animates to the view using the existing map camera animation, without changing the tab's URL or browser history. Add `--animate false` for an instant jump. Focus the intended map tab first if several are open. A command reports delivery, not visual acceptance. The endpoint and command listener are development-only and are absent from the production build. Restart Vite once if an already-running server has not picked up the new configuration.

Read the same tab's current map view with `npm run read:view` (or add `-- --url http://localhost:5174`). The response includes its last settled geographic view, a `busy` flag and the server receipt time. While the map is moving, the view is the previous settled snapshot. Snapshots are sent after movement settles and when the tab is focused or reconnects; there is no camera-frame reporting or continuous polling. Reading does not move the map or change its URL. This reports map coordinates and settings, not a screenshot.

## Local water-name editor

Run `npm run dev` and open the local map with `?water-editor`, for example `http://localhost:5173/?water-editor`. The editor is available in Explore mode only. Its component, draft storage, and import/export tools are excluded from production builds; opening the same query on the published site does not enable editing.

**Save to project** writes completed edits directly to `src/data/marine-label-overrides.json` through the local Vite development server. Names, placements, sizes, spacing, line breaks, additions, and removals are validated before a temporary file atomically replaces that maintained file. Generated Natural Earth files stay separate. The write endpoint accepts only same-origin JSON from a loopback connection and has no production or preview-server route. A revision check rejects saves if the maintained data or source placements have changed since this editor loaded, including edits from another tab or changes made in code. On conflict, export the retained browser draft and reload to reconcile it with the updated project.

A successful project save becomes the new editing baseline and clears the draft's change count and undo history. The current editor continues on that baseline without resetting the map view; other tabs see the saved project data after reloading. Browser autosave still keeps unfinished work, and failed project saves retain the draft. Project saving neither commits nor publishes changes; review and commit the resulting Git diff separately. Export/import remain available for backups and handoffs.

Selecting a name highlights its Natural Earth marine area with a purple translucent fill and dashed outline in both label layouts. **Show approximate water boundary** controls this independent overlay, including when editing handles are hidden or original placements are previewed. The geographic extent stays fixed when the label is moved, rotated, or resized; it follows the active map projection and camera, and is the same reference at both map detail levels and in both renderers. It is approximate geographic guidance, not an enforced allowed-placement area, and its generalized coastlines can differ from the displayed land. Horizontal/stacked labels use the blue move handle without a rectangular frame.

Editor-only `src/dev/water-boundaries.json` preserves source polygon coordinates and holes for all 279 names. Regenerate it with `node scripts/import-editor-water-boundaries.mjs <marine-polygons.geojson>` using the pinned Natural Earth v5.1.1 [marine GeoJSON](https://raw.githubusercontent.com/nvkelso/natural-earth-vector/v5.1.1/geojson/ne_10m_geography_marine_polys.geojson). The generated file records the source URL and SHA-256 checksum; only geometry and provenance are retained. The five ocean identities group their corresponding source pieces, including northern/southern Atlantic and Pacific pieces, without creating new names or quiz identities. Source subdivisions can remain visible within grouped ocean highlights. Natural Earth's [physical-label documentation](https://www.naturalearthdata.com/downloads/10m-physical-vectors/10m-physical-labels/) cautions that these regional boundaries are approximate. This dataset is imported exclusively by the development editor and is excluded from the published build.

Search in English or Norwegian, select a result to find it on the map, or click a visible water label. Click elsewhere on the map to deselect; panning and using editor controls preserve the selection. Drag the blue cross to move the entire placement; drag the orange path points to reshape its curve. The panel also provides two-pixel nudges, rotation, text-size adjustment, curve-path scaling, text alignment along a path, and insertion/removal of path points. **Text alignment along path** offers **Left**, **Center**, and **Right**: align the first letter to the readable start, center the text on the path, or align the text end to the other endpoint. The baseline extends beyond an endpoint when needed. Older percentage and custom-centered placements appear as **Saved position** and remain unchanged until an alignment is chosen. Choose **Center** to restore centered placement. **Automatic endpoint tangents** lets the ends follow the neighboring curve without manually managed handles. It is enabled when editing path nodes or switching to a curved layout, and can be toggled for an existing curve; untouched saved curves retain their previous shape. Numeric longitude/latitude fields allow precise point edits. Horizontal/stacked layout uses the existing language-specific line breaks and can be moved, rotated, and resized without frame controls. The **Font size** number sets a shared reference font size directly: equal values give equal font size in the same map view, independently of water-body size, label rank, path length, and layout. **Currently … px** reports the rendered font size at the current zoom. Reference pixels are normalized to a 1600px-wide map with projection scale 1 and zoom 1; the stored number stays fixed while on-screen text follows the map zoom. Geometry edits capture the currently displayed reference size before moving, rotating, switching layout, or reshaping a name, so automatic refitting cannot unexpectedly change its letter size. **Letter spacing (em)** controls the extra space between letters in both languages and layouts. The slider covers −0.1 to 0.5 em; the numeric input accepts up to 2 em. Zero removes extra spacing, negative values tighten letters, and positive values spread them apart. Spacing scales with the font size; changing it preserves the current reference font size. **Default letter spacing** restores 0.25 em for oceans or 0.11 em for other waters. Letter spacing is included in drafts and exports. **Automatic size** explicitly restores automatic fitting for that name without resetting its placement. Existing multiplier-based drafts retain their previous appearance until a new explicit size is entered; editing the number stores `textSize` and replaces the legacy `textScale` multiplier. If enlarged curved text needs more room, its baseline extends along the path's end tangents rather than clipping the name. Explicit text sizing overrides the old fitting-area visibility restriction, so enlarging a horizontal name does not make it disappear when deselected or previewed without handles.

Use Undo/Redo or reset an individual name, filter to changed names, hide handles for a clean preview, or compare all placements with their originals. While handles are enabled, the selected label remains visible below the normal size cutoff or outside its automatic fitting area, with an explanatory warning; hide handles to check normal map visibility. Use the normal language, projection, region, detail, and renderer controls to review the same draft; choose World to reach names outside the current region, and minimize the editor to reclaim map space. Placements and curves are geographic, so they follow the map as you navigate; changing projection can change their apparent curvature and angle. Preview both languages and relevant zoom levels before handoff. English and Norwegian wording can be edited independently for existing and added names. The optional **English horizontal/stacked text** and **Norwegian horizontal/stacked text** fields specify exact display text with up to four nonempty lines: press Enter for a line break and type any hyphen explicitly, for example `Nord-` followed by `Atlanteren` on the next line. Leave a field empty to use automatic wrapping. These overrides apply only in Horizontal/stacked layout; text along a path uses the single-line name. Switching layouts preserves the overrides. Text edits preserve the displayed reference font size, participate in undo/redo and comparison, and are included in autosave and exports. **Reset this name** restores both source wording and placement for catalog names.

A water name can have up to 12 placements while remaining one name entry with one boundary reference. Use the **Placement** selector or click an individual map label to choose the placement to edit. **Add placement** starts another horizontal placement at the map center, repeating the full name. **Duplicate placement** copies the selected placement's geometry, layout, and text, moving it slightly to the side for selection. **Remove placement** removes just that placement and keeps the name; if the first placement is removed, another takes its place. At least one placement remains. **Remove name** removes the entire name and all its placements from the draft.

Each placement has its own position, path, rotation, and optional **Placement text · English** / **Placement text · Norwegian**. Leave these fields empty to repeat the name using its normal wrapping rules. Explicit placement text is displayed on one line in either layout; it does not change the underlying name or other placements. To split Northwest Passage, enter `Northwest` / `Nordvest-` for one placement and `Passage` / `passasjen` for another, then move each part to the desired water corridor. Font size and letter spacing are shared across all placements. Adding a placement captures the current reference font size; multi-placement names use an explicit shared size, so **Automatic size** is available only for single-placement names. Switching between placements changes the editing handles and geometry controls; it leaves the other placements intact. Additions, removal, text, and geometry participate in undo/redo, browser autosave, export/import, and direct project saves.

**Add name** accepts English and Norwegian names, a water type, and an optional boundary reference. Choose **North Atlantic Ocean** or **South Atlantic Ocean** under **Ocean source regions** to start at that source region and highlight its boundary; northern/southern Pacific references are available too. Without a reference, the new label starts at the map center. Added names use the same placement and typography controls. **Remove name** hides an existing catalog name from the draft; enable **Show removed names**, select it, and choose **Restore name** to bring it back with its edits intact. Removing an added name deletes it from the draft; Undo recovers it during that session. Additions and removals participate in Undo/Redo, autosave, comparison with originals, and exports. These draft changes affect neither the published catalog nor quiz identities until reviewed and integrated.

Browser drafts autosave on completed adjustments and when leaving the page, using `geo-go-go-editor.water-label-draft.v1` in local browser storage. Settings reset does not clear this draft. Browser storage can still be unavailable or cleared; Export downloads `geo-go-go-water-label-edits.json` as a portable backup. If another editor tab changes the saved draft, autosave pauses with a warning so the tabs do not silently overwrite each other's work; export that tab's edits before reloading. Import replaces the current draft after confirmation when it contains changes; Undo can recover the preceding draft during that session. History keeps up to 100 snapshots and restarts when the page reloads. Version 3 exports include edited placements, their original placements, added bilingual name definitions and boundary references, removed catalog IDs, wording and stacked-text overrides, and the app version. Existing version 1 placement-only drafts and version 2 name-management drafts still load. Import rejects undefined label IDs, malformed name definitions or placements, and originals that conflict with the current source data. An unrestorable saved draft is preserved for recovery download instead of overwritten.

Local `geo-go-go-water-label-edits*.json` handoff files are ignored by Git; keep the exported file as a backup. The editor recognizes the exact draft already integrated into the maintained map by a development-only SHA-256 receipt, retains the original in `geo-go-go-editor.water-label-draft.v1.integrated-backup`, and starts a fresh draft from the updated map. This comparison ignores JSON formatting and object-key order but covers every draft value. Drafts with additional changes or unrecognized older source placements remain in recovery for download and reconciliation. Review the integrated map without `?water-editor` to see the maintained data directly.

For normal local editing, use **Save to project** when ready, then review and commit the maintained file. Alternatively, provide an export file for review and integration into the maintained label and placement data. Exporting does not modify repository files or publish changes. The handoff should validate the changes against the recorded originals, review any added or changed wording, language-specific line breaks, and removals, preserve the source/generated-data distinction, and run the build. ## Local releases

Add an **Unreleased** section in `CHANGELOG.md` only when there are pending user-visible changes. When a branch is ready to release, replace that heading with a concise versioned entry so no **Unreleased** heading remains in the published changelog, give major and minor releases a fitting name in the heading, update `package.json` and `package-lock.json` together, and commit the release preparation on that branch. From that clean release branch, run `npm run release:merge`. It checks the version, changelog, and production build, then switches to `main`, merges the branch, and creates an annotated version tag with the release name. Use `npm run release:merge -- --check` to run the checks without merging. The script requires `main` to be an ancestor of the release branch, so integrate any newer `main` changes first. After the local merge, push `main` and the tag when publication is intended; pushing `main` deploys the site through GitHub Pages.
